# 已发布内容与后台业务库对齐

## 本次修复

旧路径允许发布快照存在于 `content_releases/content_active`，而后台读取的业务表为空。本次统一了补齐逻辑：当前已发布快照是历史迁移的输入，后续运营仍采用业务草稿 → 预览 → 明确审核发布。

- 服务启动完成数据库结构迁移后，读取当前激活的发布快照，事务内补齐缺失业务记录。
- 导入、历史补齐、发布存储和回滚均调用同一 `hydrateCatalog`。发布版本和业务入库在同一事务提交；入库失败不会激活新版本。
- 不覆盖已有 ID，不更新已有草稿的内容、版本、时间戳、上下架状态或攻略步骤，不覆盖素材审核结果，不改动游客报名、收藏等用户记录。
- 覆盖线路、站点、地点、攻略与步骤、首页配置、Banner、公告、会员、权益、活动。保留原 ID、图片 URL 和已有素材 ID；旧快照没有素材 ID 时创建稳定的关联 ID。线路元数据保留指南、隐私与额外配置。
- 同一批次插入 Banner 和活动等内容时保留发布快照的排列顺序。已有配置和排序仍以草稿为准，差异页供人工核对。
- 已有攻略即使步骤为空，也视为已存在的草稿，不擅自替换步骤。

## 线上升级

必须使用与当前 H5/API 相同的数据库连接配置，以及原有 `var/media` 目录。升级前备份数据库及素材文件；不要通过导入参考示例替代线上内容。

1. 发布本次代码、构建前端；API 使用原数据库和素材目录启动。
2. API 启动时自动补齐当前已发布内容。原发布快照保持不变，游客端不会被重新发布。
3. 后台工作台 → “核对线上与草稿”，或“内容管理 → 版本与差异”，核对数量与差异。
4. 存在已有草稿时人工保留或调整；只有主动发布才影响游客端。

也可在维护窗口手动核对、执行，命令使用正常服务端数据库环境变量：

```sh
# 只读核对，不导入参考示例，不修改数据库内容
node scripts/reconcile-content.mjs
# 从当前已发布版本只补齐缺失记录
node scripts/reconcile-content.mjs --apply
```

脚本仍会执行尚未应用的数据库结构迁移；“只读核对”指不修改业务内容。重复补齐没有新增记录时不会新增内容审计记录。执行报告给出 inserted/preserved 数量和 mediaConflicts。

补齐按整个事务提交，异常会回滚。本次没有结构性数据迁移或删除操作。需要撤销一次新增补齐时应使用升级前备份，不能直接清空业务表；回滚发布版本只改变游客读取版本并补齐目标版本缺失记录，不回滚人工草稿。

## 统一导入和发布

文件导入现在只补入缺失草稿，不直接发布、不覆盖已有草稿：

```sh
node scripts/publish-content.mjs --import /absolute/path/catalog.json
```

旧的 `npm run content:publish -- 文件路径` 同样只导入草稿。无参数调用返回用法提示，不再偷偷发布参考文件。

审核发布优先使用后台按钮。脚本发布需显式提供当前草稿版本和依据：

```sh
node scripts/publish-content.mjs --publish-draft --version draft-实际摘要 --evidence '实际审核记录编号'
```

草稿版本从差异页或预览接口获取。版本变化将拒绝发布；图片版权等既有校验仍有效。`import-content-model.mjs` 仅用于空开发库首次初始化；已有线上版本时直接拒绝，防止把参考内容覆盖到线上。

## 后台与 API

| 功能 | 接口 | 权限 / 结果 |
| --- | --- | --- |
| 版本与差异 | GET `/api/v1/admin/content/comparison` | `content.read`；线上/草稿版本、各类数量、字段差异 |
| 补齐已发布内容 | POST `/api/v1/admin/content/reconcile` | `content.write`；请求 `{expectedVersion:"当前线上版本"}`，版本变化返回 409 |

差异类型：待补齐、草稿新增、草稿已下架、内容修改。展开可看线上值与草稿值，包括攻略步骤和展示排序。系统派生的审核时间、素材关联 ID 不作为业务文案差异。后台数量包含下架记录，因此不必始终等于线上数量。草稿 hash 和发布版本的格式不同，版本号不同本身不等于业务内容不同。

## 图片与环境边界

补齐恢复图片关联和元数据，不会生成、下载或凭空恢复已丢失的图片文件。若原 `/media/…` 文件不在当前服务器，需要恢复原 `var/media` 目录；外部图片保留原 URL。缺少可核验版权依据的旧图片保留待审核状态，不自动授权。已有拒绝审核的素材不会被快照重新批准。

本修复不能自动合并两台服务器或两个数据库。若 H5 和后台部署在不同环境，需先统一 API/数据库配置。代码验收不代表已经在用户的线上数据库执行过迁移。
