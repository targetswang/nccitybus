## 微信

1. **官方 preview 未运行。** `miniprogram-ci 2.1.31` 已安装、锁定和版本验证，但没有真实 AppID、代码上传私钥和 CI 出口 IP 白名单，因此没有官方 preview 二维码证据。
2. **iOS + Android 真机未验收。** WXML/WXSS/JS 在官方工具和真实微信运行环境下的行为、`wx.login`、`getPhoneNumber`、合法域名、网络重试、跨小程序乘车码跳转仍需真实设备。
3. 官方 `miniprogram-ci` 构建工具链的隔离依赖审计当前报告 76 个传递依赖问题（1 low / 18 moderate / 16 high / 41 critical）。它不进入生产运行时，但正式交付应由研发/安全团队决定是否接受该构建工具风险、隔离运行，或等待/切换上游修复版本。

## 外部凭据与现场

1. **AI live verification 未完成。** DeepSeek/Kimi 兼容调用、提案和工具权限已实现；仍需在目标环境配置真实 Key 后，由后台验证入口形成 `integration_verifications.integration='ai'` 的 passed 记录。
2. **正式短信送达未完成。** 生产 OTP 已无固定验证码；仍需配置正式短信网关，让现场手机号实际收码并完成第二步确认，形成 `sms-delivery=passed`。
3. **IVY Bus 未 live。** 缺供应商 HTTP/MQTT 凭据、真实环境、授权线路/跑法/站点映射和脱敏真实报文。代码和受控测试不能替代现场数据。
4. **乘车码跳转参数未验收。** 需要公交方/微信提供目标 AppID、Path、白名单或官方能力参数。

## 数据库与运行环境

1. PostgreSQL 16 兼容性已由 GitHub CI 实跑通过，但**最终生产 PostgreSQL 实例**仍需 release gate 做 TLS/连接/迁移 005 和 live verification 记录检查。
2. pg/mqtt 已有真实 transitive lock；最终部署环境仍需按 lock 执行 `npm ci`，并对目标镜像/OS 做漏洞扫描。
3. MQTTJS 与 IVY 的真实 Broker TLS/QoS/重连/会话恢复未现场验收。

## 内容与媒体

1. 5 站、21 POI、4 攻略、9 步骤已进入统一数据层；其中继承内容仍需甲方/运营做最终事实核验，尤其营业时间、价格、人均和商户状态。
2. 媒体工作流已经能记录版权/使用依据和地点匹配，并阻止未确认素材设为封面；但**历史候选图片本身并未自动获得版权授权**。
3. POI 自动采集只进入候选池，依赖高德服务端 Key；没有 Key 时不会伪造自动推荐结果。

## 产品边界

1. IVY 未 live 前不能承诺分钟级 ETA。当前系统对“没有实时事实”明确显示未配置/无数据，而不是生成模拟车辆。
2. H5 正式短信、微信原生手机号授权、乘车码跳转都依赖外部配置，当前不能标记为最终上线通过。
3. 当前后台已经包含内容、媒体、POI候选、用户服务、RBAC、AI提案和集成验收；不包含司机调度修改、支付核销、商城或永久轨迹仓库等未约定能力。

## 当前结论

v4.4.0-rc.1 是可继续做生产/供应商/真机验收的完整候选工程。它**不能**标记为政府/国企最终验收通过、微信真机通过或 IVY 现场通过，直到 `scripts/release-gate.mjs` 和现场验收全部解除阻塞。
